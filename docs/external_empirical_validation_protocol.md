# External empirical validation protocol (raw data + independent reference)

Status date: 2026-10-15

## Acceptance rule

A test counts as empirical validation only when all four are archived:
1. Traceable downloadable experimental input, with its origin and processing state explicitly classified (detector/raw, calibrated, or already processed).
2. A documented analysis method with units, assumptions, and versioned code.
3. An independent published/reference result for the same signal, channel, shot, time window, calibration, and convention.
4. A reproducible numerical comparison (absolute and relative difference, uncertainty where available) and a regression test.

A successful download, a plot, a synthetic fixture, a formula check, or comparison against a result generated by the same code is not empirical validation. Never silently promote processed data to raw. A missing independent comparable reference means integration test / candidate, not validated.

## GOLEM spectroscopy candidate: shot 30622

Source page: https://golem.fjfi.cvut.cz/shots/30622/Data.php

The public shot data page advertises a downloadable text file named spectra.txt_Data_.txt described as spectrally resolved radiation. It also advertises spectral-analysis outputs including temperature (electron temperature, eV) and a mean electron temperature of 20.8 eV. These are promising matched input/reference candidates, but the page alone does not establish whether the spectrum has already been corrected or processed, nor whether the temperature output uses the exact spectrum/time samples selected by a proposed TIS analysis.

Required steps before counting this as validation:
- Download the exact spectrum file through the shot page's own link (do not guess/assume a URL pattern).
- Preserve original bytes, SHA-256, retrieval timestamp, metadata/configuration and link URL.
- Inspect file header and acquisition metadata; label the input as raw detector counts, noise-corrected, sensitivity-corrected, or unknown.
- Determine wavelength calibration, instrument response, background/noise handling, selected spectral frame(s), and the documented temperature-estimation algorithm from the shot's analysis/configuration source.
- Independently reproduce the same temperature estimate from the downloadable spectrum, without importing the archived temperature as an input.
- Compare only like-for-like output: report absolute difference in eV and relative difference (%) against the archived reference; document uncertainty and any mismatched assumptions.
- Add the downloaded input only if its license/terms permit redistribution; otherwise keep a reproducible fetcher and a small metadata/expected-result manifest.

Until these checks pass, mark GOLEM 30622 as CANDIDATE; NOT YET EMPIRICALLY VALIDATED. Public evidence for the data inventory: https://golem.fjfi.cvut.cz/shots/30622/Data.php

## GOLEM spectrum metadata candidate: shot 27912

Source page: https://golem.fjfi.cvut.cz/shots/27912/diagnostics/Radiation/1111Spectrometer.ON/

The public page describes measured spectra and reports acquisition metadata (Ocean Optics spectrometer, 2048 pixels, 29 spectra, integration time 1.67 ms, noise RMS 10.6 counts), and lists both spectra.txt_Data_.txt and a relatively calibrated spectrum. This is useful for testing file parsing and distinguishing measured from calibrated data, but it is not by itself a quantitative temperature validation: a matching independent numeric result and the precise calibration/line-fitting convention must first be established.

## FAIR-MAST real-signal validation

Archive/catalog: https://mastapp.site/level1-data.html
Archive overview: https://www.ukaea.org/service/fair-mast/

Existing TIS integration coverage uses shot 29790 xmo/omaha_1lz and shot 30421 amc/plasma_current, ane/density, plus an existing EFIT grid. This is evidence of data-access and processing-path integration, not automatically validation of FFT/Welch or other physics results.

For each claimed signal-analysis validation:
- Archive FAIR-MAST shot/group/signal metadata, signal_type, units, quality field, original sample count/timebase, source URL, and downloaded file hash.
- Choose a specific signal, channel, and time interval with an independent published reference (e.g., a published mode frequency/peak or event time).
- Match sample rate, filtering, windowing, detrending, normalization, frequency convention and time window to the reference.
- Compare peak frequency/event time numerically and record resolution/uncertainty; do not treat the strongest peak as a reference without an independent source.
- Keep EFIT-reconstructed quantities explicitly classified as reconstructed/processed, not raw measurements.

## Reporting labels

- PASS — empirical: all four acceptance items above are satisfied and numerical discrepancy is reported.
- PASS — integration only: real external data downloaded and processed, but no independent comparable reference.
- CANDIDATE: source appears promising; input/reference equivalence or rawness is not yet established.
- BLOCKED: input or independent reference cannot currently be obtained.
- FAIL: a reproducible comparison exceeds the predeclared tolerance or reveals a software defect.

Do not describe the whole suite as fully validated based on a subset of successful tests. Publish a per-analysis matrix showing empirical validation status separately from unit tests, synthetic tests, and data-integration checks.
